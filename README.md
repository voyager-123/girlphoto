# GirlPhoto：本地调色标注台

一个可运行的 Python 最小版本，帮助建立“模型 1”的风格与质量评价数据。
**本版本是标注工具，不包含模型训练、自动调色、网上爬图或云端上传。**

## 运行

需要 Python 3.10+。唯一第三方依赖是 Pillow。

Windows 已有 Python 和 Pillow：双击 `start.bat`。
首次缺少依赖：双击 `setup.bat`（安装时需要网络），然后 `start.bat`。

```powershell
python -m pip install -r requirements.txt
python app.py
```

打开 http://127.0.0.1:8765 。程序只监听本机，日常运行不需要网络。
停止：在启动窗口按 Ctrl+C，或关闭该窗口。
端口被占用：`python app.py --port 8766`。
指定独立数据目录：`python app.py --data-dir D:\my-photo-labels`。

## 快速体验

1. 点击“载入演示图”，得到 6 张合成流程演示图。它们明确标记为 demo，不能作为真实照片训练数据。
2. 单图标注：为同一原图组至少两张图选择某个风格“符合”，选质量 1/2/3，保存。
3. 进入“版本比较”，选择该风格。投票左、右、平局或跳过。
4. 导出标注，获得 CSV 和完整 JSON。重启后数据仍在。

## 导入自己的照片

支持 JPEG、PNG、WebP；单张最大 25 MB / 4000 万像素。
不支持 RAW、HEIC、动画。原始文件被复制，不会移动或修改。

建议命名：

```text
001__original.jpg
001__warm.jpg
001__cool.jpg
002__original.jpg
002__warm.jpg
```

双下划线前的 `001` / `002` 自动作为原图组。也可以每个原图的各版本单独放一个文件夹。
普通散图默认每个文件名是一个原图组，不会被随意配对。
导入时可手动指定原图组（对本次全部图片生效，谨慎使用）和拍摄批次。
不同批次请避免重复使用同一个原图组名称。重复字节内容的图片不会重复导入。

- **原图组**：同一张原图的各个版本，用于配对比较。
- **拍摄批次**：同一个人、同一场拍摄等需要共同划分的数据。默认等于原图组，可人工合并。
- **split**：按照拍摄批次名称的稳定哈希分配，期望约 80/10/10，小样本不保证精确比例。
- 在照片清单改 split 会修改整个拍摄批次，避免已知相关版本跨集合。
- 程序不会做人脸识别，也不能识别你没有登记的同一个人。真实训练前仍需人工审查分组。

有比较记录的图片暂不允许改原图组，避免已有比较失去含义。请先撤销相关比较。
加入已存在的组或批次时继承它的划分。之后可在照片清单调整整个批次的划分。

## 标注约定

风格逐项标 `yes` / `no` / `unknown`；未操作的类别保持缺失（导出 CSV 为 `unreviewed`）。
**unknown、unreviewed 都不能作为负例。**新类别也不会把旧照片自动转成负例。

质量：1 明显不合格、2 基本可用、3 效果较好。未评分是 null，不是 0 分。
评颜色、明暗和处理协调性，不评人物长相。支持问题标签、备注与暂时跳过。
标注者名称用于隔离记录；切换标注者可让室友独立复标。

比较只从“同一原图组、两图均被当前标注者确认符合目标风格”的照片中生成。
左右随机，隐藏文件名与已有评分；不预先排序以暗示答案。
`tie` 是无明显优劣，`skip` 是无法判断。每组比较每位标注者保留一条当前结论，撤销历史另外保存。

快捷键：单图 1/2/3 选质量，Enter 保存；对比左右方向键投票，`=` 平局，`S` 跳过。
光标在输入框或弹窗里时不触发这些快捷键。

## 保存、撤销与导出

`data/annotations.sqlite3` 保存全部标注、比较与操作记录；`data/originals/` 保存原始图片，
`data/previews/` 是最长边 2400 px、按 EXIF 转正的预览。嵌入 ICC 配置可识别时转换为 sRGB。
预览转换失败会显示提示。细节与色彩关键任务仍应查看原文件。

“撤销上次标注”按当前标注者撤销最近一次单图保存或比较投票，可连续撤销。
分组、划分、导入和新增类别不在这个撤销栈中。

导出 ZIP **不包含图片**，包括：

- `dataset.json`：完整精确数据，包含类别定义、照片、标注、比较和操作事件。
- `photos.csv`：图片 ID、原图组、批次、划分、相对原文件路径、哈希、演示标记等。
- `quality.csv`：独立标注者的质量、状态、问题与备注。
- `styles.csv`：每个已保存标注与每个风格的关系（yes/no/unknown/unreviewed）。
- `preferences.csv`：规范图片编号 a/b、风格、标注者、结果、划分和 eligible 标记。

训练前：

1. 排除 `is_demo=true` 的照片和比较。
2. 排除 `status=skipped` 的评分与风格记录；质量为空时不计算质量损失。
3. 只有 yes/no 是有效二元风格监督；未知和未判断使用缺失掩码。
4. 比较只使用 `eligible=true`；a/b 是排序后的图片 ID，**不是显示时的左右**。
5. tie 应按平局处理，skip 不计算偏好损失。
6. 单图风格标注后续改变时，旧比较仍保留，但导出时重新判断 eligible。
7. 同图版本和同批次始终共享 split；验证/测试不用于训练。

CSV 使用带 BOM 的 UTF-8，Excel 可直接打开。以公式字符开头的文本加单引号防止误执行；
JSON 保留原始文本。请同时备份整个 data 目录，最好先停止程序再复制备份。

## 后续计划（尚未实现）

目标是逐步实现：**用户提供原图 A，选择风格 S 和强度 t，系统输出可复现的调色参数 P 和预览图 A′。**
参考图 B′ 可以用于提供风格线索；第一版按目标风格为 A 寻找较合适的处理。
这与精确复刻 B′ 的暖黄、冷绿等具体配色是两种需求，后者作为后续扩展。
本路线不要求恢复参考图 B′ 的未修原图 B，也不假设能从成片唯一反推出原始参数。

下面的清单都是待办事项，不代表当前程序已具备相关能力。按阶段验证效果，再决定是否扩大数据量和模型规模。

- [ ] 增加独立的风格强度字段。先试用少量等级和示例锚点，避免直接要求标注者打精细的 0–100 分。
- [ ] 区分“风格是否符合”“风格有多强”“调色质量好不好”。分类置信度不直接当成强度；强度未标注保留为空。
- [ ] 支持记录真正的原图与派生版本关系、调色参数、参数范围、渲染器版本和色彩空间。
- [ ] 增加同图同风格下的强弱比较，独立于现有的优劣比较；风格更浓不自动等于质量更好。

当前的原图组仅用于关联照片，程序还不能识别组内哪张是真正的原图，也没有导入调色参数的功能。
在加入风格强度字段之前，不要把强度混进现有质量分数。

### 2. 收集小批真实数据，先验证标注是否可靠

- [ ] 先用约 50–100 张独立原图，每张制作 3–5 个代表性版本，试跑导入、标注、比较和导出流程。
- [ ] 覆盖室内外、不同光源、肤色、曝光和背景；同一原图加入暖黄复古、冷绿复古等差异，以及适量明显处理不当的版本。
- [ ] 由两位标注者独立复标一部分样本，检查质量等级和偏好是否足够一致；有分歧时保留个人意见。
- [ ] 不把“网图是高分、原图是低分”作为自动标签；未修照片可能质量很好，网图也可能处理不当。
- [ ] 检查同人、同场拍摄、近重复图片和各调色版本的分组，确保相关样本不跨训练、验证、测试集。

上述数量只是流程试验的起点，不是训练效果保证，也不是正式模型的数据量结论。
后续根据独立验证集表现、各风格覆盖和新增数据的收益决定是否扩充。
真实照片只在本地数据目录保存，使用自己拍摄或获得相应使用许可的数据。

### 3. 训练模型 1：风格、质量与偏好评价

- [ ] 实现数据加载、缺失标签掩码、固定的数据划分及可复现训练配置。
- [ ] 先建立一个小型基线：共享图像特征，分别输出多标签风格判断和质量等级；有强度标签后再加入强度预测。
- [ ] 用同一原图、同一风格下的版本比较训练偏好排序，学习“这个场景中哪种处理更协调”。
- [ ] 为适配评价引入原图和目标风格作为条件，比较单图评分与“原图 + 修图 + 风格”评分的效果。
- [ ] 使用适合等级标签的质量目标，并对偏好中的平局、跳过和标注者分歧分别处理。
- [ ] 在独立验证集记录各风格分类表现、质量排序表现和人类偏好一致率，按场景检查失败案例。

要验证的关键能力是：在人物和构图相同的情况下，模型能否区分肤色发脏、曝光失衡、颜色不协调等处理差异。
不能只因人物长相、服装或背景而给高分。不同人的偏好可能不同，不预设每张图只有一个客观最优的复古版本。
模型 1 达到足够的人类偏好一致性后，才将它用作参数选择的评价器。

### 4. 实现调色引擎，先跑通参数搜索基线

- [ ] 定义少量可控参数，如曝光、对比度、色温、色调、饱和度和阴影抬升，固定取值范围与处理顺序。
- [ ] 实现确定的渲染函数 `A′ = render(A, P)`，确保同一版本引擎、同一原图和参数能复现同一结果。
- [ ] 明确参数属于本项目自己的引擎；如果要导出到 Lightroom 等软件，另做参数映射和效果校验。
- [ ] 建立“原图 + 目标风格 + 强度 → 生成多组候选参数 → 渲染 → 模型 1 评价 → 返回候选”的基线。
- [ ] 综合风格匹配、目标强度、质量与内容保留进行筛选；限制极端参数，保留不调整或减弱处理的选项。
- [ ] 支持强度为零时保持原图，并检查随强度变化是否平滑；参数线性缩放不直接等于感知强度线性变化。

这一阶段可以先用有限候选或黑盒搜索，不必先训练模型 2。
先检查评分高的结果是否也得到人的认可，避免搜索只利用评分器的漏洞。

### 5. 训练模型 2：根据原图、风格和强度预测参数

- [ ] 用已知参数生成的版本、经人工验证的搜索结果和真实偏好，整理参数学习数据。
- [ ] 实现 `P = 模型2(A, S, t)`，并通过同一个调色引擎生成 A′。
- [ ] 先学习可靠的参数示例，再探索通过模型 1 的反馈进一步优化；没有参数标签时，不假装图片自带真实参数。
- [ ] 如果使用梯度训练，验证渲染器及评价路径是否可微；不可微时使用搜索或其他适用方法。
- [ ] 使用模型 1 作为固定评价器时冻结其权重，并用独立人工评估检查结果，避免只追逐一个分数。
- [ ] 对比固定预设、候选搜索和模型 2 的效果、速度及失败率，确认训练模型 2 带来的实际收益。

计划中的流程：

```text
原图 A + 风格 S + 强度 t
          ↓
      模型 2 → 参数 P
          ↓
    调色引擎 render(A, P) → 结果 A′
          ↓
 模型 1 评价 + 独立人工比较 → 用于训练与效果验证
```

“参考图模式”可先用模型 1 提取 B′ 的风格线索，再允许用户确认风格和调整强度。
参考图自身的质量分数不是结果必须达到的目标，也不应直接复制参考图的曝光等参数。
若要跟随参考图的具体配色，再增加参考图特征作为模型 2 的输入，并单独验证。

### 6. 做成可试用的自动调色功能

- [ ] 展示多种候选，让用户选择；将明确同意用于改进的偏好反馈纳入后续数据。

**最近一轮优先做第 1、2 阶段：先让真实照片的标注标准和数据记录稳定，再开始模型训练。**

## Git 与开发

代码使用 Git 管理；data、虚拟环境、导出和数据库默认忽略，不提交个人照片。
GitHub 仓库：[voyager-123/girlphoto](https://github.com/voyager-123/girlphoto)。
上传的是代码与文档，照片、标注数据库和个人代理配置不上传。

```powershell
python -m unittest discover -s tests -v
git status
git log --oneline
```

前端不依赖 npm、CDN 或外网。服务端是标准库 HTTPServer + SQLite，图像处理用 Pillow。
这是单机、轻量团队复标原型，没有账号鉴权、任务分配或大型图片库的分页优化；不要暴露到公网。
原图组超过数百个版本会产生很多候选对，建议每组先保留 3–10 个代表版本。
